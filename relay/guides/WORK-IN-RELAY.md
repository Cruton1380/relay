**Is:**
- ✅ Commits to filaments
- ✅ Dependency creation
- ✅ Authority accumulation via history
- ✅ Visible, traceable contribution

**Your work IS your filament tree.**

## 🏢 HOW YOU GET PAID

### **Money Flows to Filaments, Not Roles**

**Traditional model:**
- Job title → salary
- Manager decides raise
- Politics > contribution

**Relay model:**
- Commits → compensation
- Dependency weight = value
- History > opinions

**How it works:**
1. You advance filaments (commits)
2. Other filaments depend on yours
3. Dependency weight accumulates
4. Compensation flows to weight

**Victory = becoming a dependency.**

## 🎯 HOW YOU ADVANCE (NO LADDER)

### **There Is No "Promotion"**

**Instead:**
- Expand your filament tree (new branches)
- Deepen influence (more dependencies)
- Accumulate authority (history weight)

**Advancement = growing capability + dependency weight, not title changes.**

---

### **Example: From Junior to Senior**

**Junior state:**
- 1 filament branch (single project)
- Few dependencies
- Low authority weight
- Receives lots of delegation

**Senior state:**
- 5+ filament branches (multi-project)
- Many dependencies (others rely on you)
- High authority weight (history proven)
- Delegates to SCVs + junior peers

**No title change. Just tree growth.**

## 🏢 MANAGERS ARE SCOPE HOLDERS (NOT COMMANDERS)

### **What Managers Actually Do:**

**Not:**
- ❌ Command tasks
- ❌ Approve work
- ❌ Control your time

**Instead:**
- ✅ Hold scope (define boundaries)
- ✅ Set constraints (resources, time, zones)
- ✅ Resolve conflicts (when filaments clash)
- ✅ Delegate influence (temporary authority)

**Managers = architects of constraint, not lords of obedience.**

## 🚀 HOW TO START WORKING

### **Daily Flow:**

**1. Enter Relay**
- HUD loads with YOUR state
- Globe shows buildings/tasks
- Gauges show constraints

**2. Check Build Queue**
- What's in progress?
- What's blocked?
- What needs attention?

**3. Navigate to Work Location**
- Home → Transit → Office
- Each building = capability anchor
- Proximity channels activate

**4. Enter Department**
- Access derived from identity filament
- Traversal = proof of access
- No "login" or "permissions UI"

**5. Inspect Work**
- Select task → see filament history
- Zoom into commits → see formulas/code
- Check dependencies → understand impact

**6. Make Commits**
- Advance filaments (new commits)
- Lock escrow if needed
- Delegate to SCVs if appropriate

**7. Monitor HUD**
- Gauges update in real-time
- Commitment capacity consumed
- Time pressure increases/decreases

## 🛠️ HOW TO WORK WITH SCVS

### **SCVs Are Your Units**

**Example: Procuring Supplies**

**Step 1:** Create task
```
Task: "Source widgets for production line"
Assign to: SCV-Procure-01
Budget: $5,000 escrowed
Deadline: 3 days
```

**Step 2:** SCV works
- Searches suppliers
- Compares prices
- Checks availability
- Generates proposal

**Step 3:** SCV returns proposal
```
Option A: Supplier X, $4,200, 2-day delivery
Option B: Supplier Y, $4,800, 1-day delivery
Option C: Supplier Z, $3,900, 4-day delivery

Recommendation: Option A (best value + timeline)
Evidence: [price quotes, delivery confirmations]
```

**Step 4:** You select
- Choose Option A
- Commit selection
- Escrow locks $4,200
- Order placed

**SCV multiplied your capacity. You remained accountable.**

## 🗳️ HOW VOTING WORKS

### **Voting = Force Lending (Not Opinion)**

**You don't vote to "express preference."  
You vote to lend legitimacy.**

**Example: Office Relocation Vote**

**Scenario:** Company proposes moving HQ

**Step 1:** Vote appears in HUD
```
Vote: Relocate HQ to Building B
Current influence: 125 points
Delegation allowed: Yes
Expires: 48 hours
```

**Step 2:** You decide
- **Delegate:** Lend your 125 points to proposal
- **Oppose:** Withhold points
- **Abstain:** No action

**Step 3:** Vote decays
- Your influence decays over time
- Continuous > spike
- Duration matters

**Step 4:** Outcome
- If proposal succeeds: Your influence contributed
- If proposal fails: Your influence preserved
- Either way: History recorded

**Voting is commitment, not polling.**

## 🏗️ HOW TO CREATE WORK

### **You Don't "Assign Tasks." You Create Dependencies.**

**Example: Starting New Project**

**Step 1:** Define filament scope
```
New filament: project.widget_redesign
Scope: Redesign widget UI for mobile
Owner: You
Participants: [designer.alice, engineer.bob]
```

**Step 2:** Create initial commits
```
c0: Project charter (goals, constraints)
c1: Design requirements
c2: Technical constraints
```

**Step 3:** Fork branches
```
project.widget_redesign
  ├─ design.mockups (Alice's branch)
  ├─ eng.prototype (Bob's branch)
  └─ pm.timeline (Your branch)
```

**Step 4:** Dependencies emerge
- Bob's prototype depends on Alice's mockups
- Your timeline depends on both
- Completion requires all branches to converge

**Victory = when other projects depend on yours.**

## 💰 HOW RESOURCES WORK

### **You Don't "Earn Money." You Earn Capacity.**

**Three resource types:**

**1. Attention (finite, recoverable)**
- Consumed by: Active tasks, open commitments
- Recovered by: Rest, distance, disengagement
- Prevents: Infinite micromanagement

**2. Commitment Capacity (bounded)**
- Consumed by: Active commitments
- Freed by: Task completion, delegation
- Prevents: Overcommitment

**3. Escrowed Resources (locked)**
- Consumed by: Pending orders, locked budgets
- Freed by: Task completion, escrow release
- Prevents: Double-spending

**HUD shows all three in real-time.**
